# TP4 adapters

The adapters of the TP4 production line ([docs/tp4.md](tp4.md)). All are import hooks in `adapter/sitecustomize.py`, gated by an environment variable, off unless the variable is set, and each refuses to boot if the engine symbol it patches has drifted. `engram_prefetch`, `wo_a_w8`, `draft_tau`, `draft_head_fp8`, `block_verify`, `folded_result_fence`, `verify_cap` and `autotune_keep` were already used by the TP3 profile; they are listed for completeness.

| File | Gate | What |
|---|---|---|
| `adapter/shared_pad_k.py` | `DSV41_SHARED_PAD_K` | Shared-expert `down_proj` K padded 576 → 640 with re-blocked scales, so the shape stays on the b12x MXFP8 kernel instead of the CUTLASS fallback |
| `adapter/indexer_chunked.py` | `DSV41_INDEXER_CHUNKED` | sglang#39187 adapted to the `dev-dsv41` image backend (`self.candidate_masks`) |
| `adapter/indexer_chunked_v3.py` + `spark_prefill_dense.py` | `DSV41_INDEXER_CHUNKED`, `SPARK_PREFILL_TP_SPLIT` | sglang#39187 for the `candidate_metadata` backend of the `dsv4.1` branch, plus the SG18 prefill TP split inside the chunked path; `sitecustomize` picks v1 or v3 from the stock source |
| `adapter/engram_prefetch.py` | `DSV41_ENGRAM_PREFETCH` | Forks a side stream after `EngramHasher.forward`, runs the ids copy, the row-store host callback and the row copies for every Engram layer there, and joins at the layer's gather; `DSV41_ENGRAM_PREFETCH_CHECK=1` re-runs the synchronous path and counts differing gathers (0 over benches and needles) |
| `adapter/wo_a_w8.py` | `DSV41_WO_A_W8` | After load, builds an fp8 twin (e4m3 + one exponent per 32x32 block) of every bf16 `wo_a` and keeps it only when it reproduces the weight exactly; the 2–8-row verify/draft path then runs a copy of the stock `_wo_a_partial` that loads the twin and rebuilds the same bf16 tile in registers. Other shapes stay on the stock kernel |
| `adapter/draft_tau.py` | `DSV41_DRAFT_TAU` | Scales the per-request temperature of the folded DSpark draft sampler; the same tensor drives draft sampling and the draft probabilities in the rejection sampler |
| `adapter/draft_head_fp8.py`, `adapter/draft_head_fp8_tp4.py` | `DSV41_DRAFT_HEAD_FP8`, `DSV41_DRAFT_HEAD_FP8_IMPL=tp4` selects the TP4 variant | When the draft attaches the target's vocab-parallel LM head, keeps an fp8 copy (e4m3 + one power-of-two scale per 32x32 block) and computes the draft's block logits from it with a Triton kernel (up to 64 rows in 16-row tiles; the TP4 variant sizes the row tile to the batch, 16/64/128 up to `DSV41_DRAFT_HEAD_FP8_MAX_M`, default 64, so the head is streamed once per call, with the same fp32 logits per row); the target keeps the bf16 head |
| `adapter/block_verify.py` | `DSV41_BLOCK_VERIFY` | Replaces `AcceptSampling` (sampled rows) with block verification: weights w_i = min(w_{i-1} p/q, 1), joint accept probabilities h_i, correction token from max(w p − q, 0); same target probabilities (temperature/top-k/top-p) and draft probabilities the stock sampler uses; ragged verify keeps the stock rule |
| `adapter/folded_result_fence.py` | `DSV41_FOLDED_FENCE` | Clones the six `AcceptOuts` tensors on the folded path so the overlapped D2H copy never reads the verify graph's persistent buffers. With `DSV41_EAGER_GLUE` containing `fence`, the six copies are one kernel (`eager_glue.fused_clone`: the int32 views concatenated into one fresh buffer and sliced back, same bytes) |
| `adapter/verify_cap.py` | `DSV41_VERIFY_CAP` | Per-request verify length inside the fixed `[bs, 6]` verify: an in-graph Triton kernel copies the anchor row's router ids and weights over the rows past each request's live length (one launch per layer, 38 us per step for 43 layers), acceptance is capped through `cutoff_verify_lens`, and the live length comes from the draft confidence head (built in static mode, which the engine otherwise skips) as a stopping rule over earlier drafts only. `1`..`5` fix the verified drafts instead (for measurement); `conf:a,b,c,d` sets one threshold per draft 2..5; `DSV41_VERIFY_CAP_LOG=<file>` records the confidences, live length and accepted drafts per step (rank 0, costs a sync per step). A fit on 6,074 uncut steps found per-position thresholds worth only +0.4 % over the single 0.1, and a perfect cut worth +15.5 %: what is left is in the confidence head, not the rule |
| `adapter/wo_a_w8.py` (mid, drop) | `DSV41_WO_A_W8_MID`, `DSV41_WO_A_W8_DROP` | `MID`: a second Triton kernel for 9-192 verify/draft rows from the fp8 twin (split-K partials summed in a fixed order). `DROP`: after a dequantized copy of each twin is checked bit-identical, the bf16 weight becomes a zero-stride view of a one-element tag and every call is served from the twin; prefill dequantizes into a fresh buffer per call (a single shared buffer raced between the target and draft streams) |
| `adapter/router_live.py` | `DSV41_ROUTER_LIVE` | Reads `sglang.kernels.ops.moe.moe_fused_gate`'s source, adds a `live_ptr`/`LIVE_STRIDE` argument to `_router_triton_kernel` so each row loads its request's anchor row when its position is past the live length, writes the patched module to a temp file (Triton needs a real file) and imports it; `verify_cap` calls it for target-verify gates. Any drift in the engine source fails the build at import |
| `adapter/replicated_split.py` | `DSV41_REPLICATED_SPLIT` | Per-instance `ReplicatedLinear.forward` override for layers whose prefix ends with a listed suffix, at M <= `DSV41_REPLICATED_SPLIT_MAX_M` (96). Tiles of 128 output rows are spread over the TP ranks (4/4/3/3 for 14), the weight and its scales (row-indexed, or the flat 128x4-swizzled MXFP8 buffer whose 128-row tiles are contiguous) are sliced, and the same quantized linear runs on the slice; outputs are all-gathered (padded to the widest slice). At the first eager call each rank compares its slice against the stock layer on the real input and three random ones, bit for bit, and the ranks agree with a MIN all-reduce: a layer is split on all ranks or on none. `DSV41_REPLICATED_SPLIT_WINDOW` (default 1): a rank whose slice is narrower than the widest runs its GEMM on a window of the widest width over the real weight that contains its tiles (views, no copy), so no pad fill + copy precedes the gather; the neighbour columns are dropped after it (0 = exact slices + pad). `DSV41_SPLIT_COMPACT_GATHER=1`: each rank sends only its own columns and the RoCEnante columns kernel (`b12x.comm.roce` `all_gather(columns=...)`, added by `scripts/b12x-roce-columns-gather.patch`) writes them at their stock offsets, with no pad, movedim or cat; outside RoCE (other groups or sizes, `=minimal`, or the ring package, which has no columns kernel) a dim-0 gather plus one cat. The first eager call of each variant, layer and M runs it next to the old path and compares every byte, rank-agreed; a difference keeps the old path |
| `adapter/draft_main_proj.py` | `DSV41_DRAFT_MAIN_PROJ_SPLIT` | The draft's `project_target_hidden` for up to 16 rows: the MXFP8 `main_proj` is read out of the layer itself (applied to identity rows, which is exact), each rank keeps its 1280 output columns as e4m3 with per-(row, 32-column) power-of-two scales (checked to reproduce the weight exactly), a Triton GEMV computes them from the bf16 activation and the columns are all-gathered |
| `adapter/roce_gather.py` | `DSV41_ROCE_GATHER` | Sets the RoCEnante runtime's `max_gather_bytes` (the SG17 overlay builds it with 0) up to the slot size, prepares the gather launcher and its padded scratch before graph capture, and routes `PyNcclCommunicator.all_gather` calls whose shard fits through `roce.all_gather` |
| `adapter/moe_b12x_next.py` | `DSV41_MOE_B12X_NEXT` | Routed MoE on b12x main (package `b12x_next`, fetched and renamed at build by `scripts/fetch_runtime.sh`) instead of FlashInfer's CUTLASS MXFP4 path, which cannot run the 576-wide per-rank experts of `EP_SIZE=1`. Accepts the width in `create_weights`, repacks the checkpoint bytes in place (no extra weight memory), swaps the fused MoE function, prepares one execution plan per decode/verify row count of the CUDA-graph list plus a prefill ladder up to the chunk size, and pins two plans b12x's heuristic gets wrong for 576-wide experts: `dynamic` at <= 8 rows (the `micro` plan re-reads an expert slice per token and slot) and 64-row tiles from 2048 rows (16-row tiles re-stage the weights per 16 rows). At EP1 the router's ids go straight to b12x (it skips the -1 padding ids); at EP2 an in-graph kernel maps them to local experts. Refuses to boot on any drift of the pinned b12x commit or the engine symbols it patches. Under `DSV41_MOE_B12X_NEXT_DETERMINISTIC=1` the <= 8 row plans keep the Triton route planner (`DSV41_MOE_B12X_NEXT_DET_TRITON`, default 1; runtime patch `scripts/b12x_next-det-triton-planner.patch`, internal planner with a warning without it; triton == internal bit for bit), and the barrier words are re-zeroed in one fill (`b12x_next-barrier-zero.patch`). `prequant_views()` exposes the plan's packed MXFP8 input for prefill SP stage 2b (`b12x_next-prequant-input.patch`) |
| `adapter/hc_fused.py` | `DSV41_HC_FUSED` | For prefill-size inputs (>= 512 rows) the hyper-connection mix statistics are accumulated in one pass over K instead of 80 partial slices plus a reduce, with the same partial sums in the same order (bit-identical); decode sizes keep the stock kernels, which run hidden on a side stream. Compares itself with the stock kernels on the first live call and falls back for good on any differing bit |
| `adapter/prefill_sp.py` | `DSV41_PREFILL_SP` | Prefill sequence parallel for chunks of >= 2048 rows that split evenly over TP (eager prefill only; decode, verify, the draft and CUDA graphs never enter it): attention and MoE take all-gathered inputs and return reduce-scattered outputs, and the per-row work between them (hc post/combine/norm/mix stats, the Engram `wkv` GEMM and gate) runs on the rank's quarter of the rows. Every row-count-dependent kernel choice keys on the full chunk (`sp_logical_rows()`), so each per-row kernel gives the same bits on a quarter as on the full chunk; the `wkv` shard GEMM is self-checked per chunk size and rank-agreed. `DSV41_PREFILL_SP_EXACT=1` keeps the all-reduce (bit-identical to stock), `=comm` swaps only the collectives, `DSV41_PREFILL_SP_DEBUG=compare` runs the stock op next to each sharded one and logs any differing bit. Refuses to boot on engine drift. `DSV41_PREFILL_SP_FP8=1`: MXFP8 attention-input gathers, self-checked per chunk size. `DSV41_PREFILL_SP_FP8_MOE=1` (stage 2b, off, not in the production line): MXFP8 MoE-input gathers with the router and top-k on the shard, written straight into the b12x_next plan's input storage; bit-exact and self-checked per chunk size, but flat on real-text prefill |
| `adapter/l2_prefetch.py` | `DSV41_L2_PREFETCH` | Learns, per decode/verify graph shape, which MXFP8 linears and router GEMM follow each RoCE collective, and during capture forks a side-stream kernel at every collective that issues `cp.async.bulk.prefetch.L2` for the first `DSV41_L2_PREFETCH_MB` (6) of those weights, joined at the next collective. Forwards on the NCCL path (the pre-capture autotune dummy run) are never learned; a captured shape whose plan does not match logs `MISMATCH` and runs without prefetch. `DSV41_L2_PREFETCH_WOA=1` (production): the MXFP8 linear before `wo_a` (wq_b, or the indexer's last linear) opens a window that prefetches `DSV41_L2_PREFETCH_WOA_MB` (6) of `wo_a` while the attention core runs, joined at the end of the forward (-0.4 ms/step). The other sub-gates (`_AHEAD`, `_DRAFT`, `_ENGRAM`, `_LMHEAD`, `_SKIP_N`, `_WOB_MB`, `_MOE`) were measured flat or slower and are not recommended; they default to off. Hooks both `b12x.comm.roce` and `b12x.comm.roce_ring` |
| `adapter/spec_sync_free.py` | `DSV41_SPEC_SYNC_FREE` | Drops the per-step rank-0 broadcasts of the DSpark decode step whose values are already identical on every rank: the draft graph's sampled token per Markov step (`draft`: the draft noise becomes a counter-based Philox stream keyed by a seed broadcast once, so every rank draws the same numbers; greedy rows bit-identical to stock), the verify epilogue's three (`accept`) and verify_cap's live length (`vcap`). `merge` packs the epilogue's three into one broadcast instead; `audit` keeps every broadcast and counts on device how often a rank differed from rank 0 (0 in ~60k checks on the fleet). `all` = draft,accept,vcap. `DSV41_SPEC_SYNC_FREE_AUDIT_EVERY` (1024) sets the audit readout interval; `DSV41_SPEC_SYNC_FREE_SEED` fixes the noise seed (default: rank 0's torch seed, broadcast once at init). Install failure raises, since a rank that kept a broadcast its peers dropped would hang |
| `adapter/eager_glue.py` | `DSV41_EAGER_GLUE` | Cuts the eager kernels between the draft and target-verify graphs, bit-identically. `fence`: the folded fence's six clones as one copy; `stage`: `stage_sampling_params` skipped while its inputs are unchanged; `vcap`: verify_cap's live-length update captured at the end of the draft graph for sizes no smaller batch pads into; `vcapk`: that update as one Triton kernel (in the association torch's cumprod uses). `all` = fence,stage,vcap,vcapk; `vcapk` is checked against the torch ops on the first `DSV41_EAGER_GLUE_CHECKS` (8) eager calls and turns off for good on any difference. `tvglue` / `dglue` (replay prep through SGLang's metadata glue graph) are dropped: the prep reads a per-step `out_cache_loc` tensor, so a glue graph would replay a stale address; the names parse and install nothing |
| `adapter/ab_variant.py` | `DSV41_AB_VARIANTS` (>= 2) | **Test only.** In-boot A/B: one CUDA graph set per flag variant (`DSV41_AB_V0`, `DSV41_AB_V1`, ...), switched at runtime through a flag file that rank 0 broadcasts with the scheduler's requests, so every rank replays the same variant on the same step. Install-time gates are unioned, adapters read their gate per call through `ab_variant.env()`. Flags outside its registry are refused (they would be the same in every variant), as are identical variants (unless `DSV41_AB_ALLOW_AA=1`), more than 8 variants, and TP ranks with a different config hash (variant specs, base env and the adapter sources). `DSV41_AB_MAX_BS` captures larger shapes once, for variant 0 only. Driven by `scripts/ab_inboot.py`; `scripts/repeat_sha.py` checks greedy repeatability. Roughly doubles decode graph memory: never in production |
| `adapter/autotune_keep.py` | `DSV41_AUTOTUNE_KEEP` | Replaces the per-rank byte digest of the FlashInfer autotune cache gate with the load decision (as in sglang#40420) plus a per-rank launch fingerprint written next to the cache after tuning, so a configuration change never leaves one rank with a partial hit. Under the in-boot A/B harness the fingerprint uses the recorded base env (`DSV41_AB_*` excluded), so an A/B boot keys like a boot of its base env |
| `adapter/fast_load.py` | `DSV41_FAST_LOAD` | Checkpoint tensors this rank will copy (owned experts, no Engram tables) read eagerly by a 16-thread `pread` pool into 256 MiB pinned slabs and returned from `safe_open` as views; at `EP_SIZE=1` (`DSV41_FAST_LOAD_TP_SLICE=auto`) only the rank's slice of each expert is kept, behind a full-shape stand-in whose `narrow` returns it and which refuses any other access; the model's async copies paced to a byte budget so the reads stay just ahead; the DSpark draft load opens only the `mtp.*` shards. Loader-only: the model still does every narrow and copy |

Tests: `tests/test_indexer_chunked.py` and `tests/test_indexer_chunked_v3.py` lift the stock function out of the engine's source, drive it and the backport with deterministic fake kernels, and require bitwise-equal `page_indices`, `raw_indices` and candidate masks over six scenarios (ragged batches, empty requests, full and tail-only mask publishing, mask consumption, one row per chunk up to a single chunk). Both run inside the image build (`Dockerfile` runs v1, the canary images v3), together with the thinking-alias, output-cap and loop-abort tests; the canary-roce build also runs the CPU tests of the adapters above (fast load, prefill SP, b12x MoE, replicated split and compact gather, verify_cap, spec_sync_free, eager_glue, the A/B harness) and the ring RoCE test; the `tests/*_gpu.py` files need a GPU and document their own `docker run` line. `tests/test_fast_load_pacing.py` (all images) checks the copy pacing; the in-image checkpoint test for the eager reads (bitwise equality against the stock `safe_open` for every dtype, draft shard filtering, memory release) needs the weights mounted and is described in `docs/fast-load.md`.
